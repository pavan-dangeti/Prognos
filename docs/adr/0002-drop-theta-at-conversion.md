# ADR-0002: Drop `theta` and `Xv` at the parquet conversion boundary

Date: 2026-10-09
Status: Accepted

## Context

Each N-CMAPSS HDF5 file stores per unit:

- `W` — scenario descriptors (altitude, Mach, throttle resolver angle, fan inlet
  temperature). Known on a real aircraft.
- `Xs` — 20 measured condition-monitoring signals. This is what sensors produce.
- `Xv` — virtual sensor estimates, inferred from the health parameters.
- `theta` — true health parameters: per-module flow and efficiency degradation.
- `op_data` — per-cycle operational aggregates.

`theta` is generated by the same simulator process that generates `Xs`. It is not
merely correlated with RUL; it is close to a linear encoding of it. A model given
`theta` will score well and predict nothing useful, because no equivalent signal
exists on a real engine.

## Decision

The HDF5 to Parquet converter emits only `W` and `Xs` plus derived columns.
`theta` and `Xv` are never written to Parquet. Model input matrices are built from
an explicit column allowlist, and a test asserts that no `theta` or `Xv` column
name survives into any model input.

## Rationale

Dropping at the conversion boundary makes the guarantee structural rather than
conventional. The dangerous path is a filter applied at training time and forgot
at inference time, or a feature builder that reaches for whatever is in the
frame. If the columns do not exist downstream of conversion, neither mistake can
happen.

The allowlist plus test is a second line of defence, not the primary one: it
catches a future contributor who adds a column directly from HDF5.

## Consequences

- Direct comparison against published hybrid results that use calibrated sensor
  estimates or health parameters is not possible on equal footing. We compare
  against the data-driven setting (`W` + `Xs`) instead.
- The conversion is not reusable for the health-indicator work that legitimately
  needs `theta`. If that is ever wanted, it needs a separate, clearly labelled
  conversion path.

## Alternatives

- Carry all groups and filter at training time: rejected, the filter becomes
  load-bearing and silently omittable.
- Carry all groups and filter in the model wrapper: rejected, same problem one
  layer up.
